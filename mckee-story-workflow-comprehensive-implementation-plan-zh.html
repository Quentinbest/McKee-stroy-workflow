McKee Story Workflow 全面优化实施计划

1. 执行摘要

本项目不缺少故事理论、专业 Critic 或生成能力。当前瓶颈是缺少一层统一的执行控制： 哪个 Skill 在什么时候运行、依赖哪些文件、产生什么证据、何时允许推进、失败后回溯到哪里，以及如何在跨会话和批量生产中保持一致。

54+ 现有 Skills / Agents

覆盖 Premise、Genre、Structure、Character、Scene、Subtext、Prose、Audit、Revision 与 Publish。

8 实施阶段

从基线冻结和 Codex 原生化开始，最终形成发布、读者观察、复盘与持续学习闭环。

P0→P2 实施优先级

先解决路由、路径、状态与恢复可靠性，再建设编排，最后扩展并行和规模化生产。

核心判断

判断 含义 实施决定
主要缺口是控制平面，不是专业能力 继续增加 Critic 会增加复杂度，却不能自动提升可靠性。 冻结新增 Specialist，优先建设路由、契约、状态、闸门和恢复。
小说创作不能照搬软件自动修复 机械错误可以自动修；主题、声音、人物、结局属于作者主权。 将决策分为机械、创作判断、用户挑战三类。
长篇稳定性取决于文件系统而非会话记忆 聊天上下文会压缩、丢失或污染，Artifact 才是可恢复事实源。 所有锁定决策、审计结果、失效范围和学习必须落盘。
规模化来自标准化边界，不来自无限并行 多个 Agent 若共享未冻结 Canon，会制造结构和声音分裂。 并行仅用于隔离候选、Critic 和独立场景批次，合并前必须通过 Canon Gate。
目标结果： 用户可以从一个故事种子开始，通过少量高层命令完成发现、计划、结构、场景、章节、审计、修订、发布和复盘； 每一步均有文件证据、质量闸门、明确下一步和失败回退路径。

2. 设计原则与边界

借鉴 gstack 的不是软件术语，而是让复杂工作稳定收敛的组织原则。

原则 在小说工作流中的解释 允许自动化 必须保留作者决定
专业角色单一职责 Premise、结构、声音、连续性、潜台词等维度分开运行。 路由、输入准备、报告聚合。 冲突维度优先级和最终取舍。
Artifact-first 锁定事实、Canon、审计、修订与学习不得只留在对话里。 模板创建、完整性检查、状态回写。 锁定或解锁核心创作决定。
Boil the Lake 补全可穷尽的连续性、Ledger、缺失状态和质量检查。 完整扫描、账本更新、过期检测。 是否扩写正文、世界观或支线。
Search Before Building 先检查类型传统、研究材料、已有 Canon 和已尝试方案。 本地检索、资料清单、重复方案检测。 是否遵循或有意识地打破类型惯例。
User Sovereignty 系统推荐，作者决定；模型共识不能替代创作权。 机械选择和低风险补全。 主题、人物真相、关键牺牲、结局、声音和审美禁区。
Evidence-based Done “完成”意味着 Artifact、Predicate、审计和状态证据齐全。 验收检查与 Dashboard 判定。 艺术上是否达到作者的完成感。

不可机械照搬的做法

测试覆盖率 ≠ 艺术质量

应追求 Predicate Coverage、Canon Coverage 和 Reader-risk Coverage，而不是把文学判断伪装成数字真理。

Fix-first 仅适用于机械缺陷

连续性、路径、注释泄漏可以自动修复；声音、节奏和潜台词默认应先诊断，再由作者批准修订。

完整性不等于内容膨胀

应补全缺失的 Ledger、失败路径和状态，不应自动增加人物、设定、支线或字数。

并行不等于共享 Canon

候选方案和盲审可以并行；同一 Canon 上的正文并行必须有范围锁、版本和合并闸门。

3. 目标系统架构

目标架构分为四层：用户意图层、控制平面、专业执行层和持久化 Story Repository。 控制平面不写小说，它负责选择执行者、准备上下文、检查证据、管理状态和决定何时停止。

四层职责

层级 负责 不负责 核心产物
用户意图层 目标、限制、创作判断、批准和否决。 重复执行机械检查。 Intent Brief、Creative Decisions。
控制平面 路由、契约、状态、闸门、恢复、失效传播、学习。 代替 Specialist 进行深度创作或批评。 Dashboard、Checkpoint、Decision Log。
专业执行层 在单一维度生成、诊断或修订。 擅自改变上游锁定事实。 Premise、Spine、Scene、Audit 等。
Story Repository 保存 Canon、版本、证据、状态和历史。 依赖聊天记忆推断事实。 结构化项目目录。

4. 目标生命周期

目标流程将既有 Seed → Premise → Scene → Chapter 主线扩展为完整闭环。 每个箭头都代表一个可验证的 Artifact 交接，而不是一句“继续”。

1. Discover提取 Haunt、目标读者体验、类型机会、长度和审美边界。
2. Contract锁定 Premise、Genre Contract、Controlling Idea、Persona。
3. Plan构建 Cast、World、Spine、Act、Sequence、Chapter Strategy。
4. ApproveReadiness Dashboard；作者确认创作判断和 User Challenges。
5. DraftScene Card → Beat Sheet → Subtext → Prose，按批次提交。
6. Assemble场景组合为章节，补充转场、章首和章尾钩子。
7. Audit / Revise智能 Critic 路由、Revision Queue、定点修复与回溯。
8. Publish / Learn最终组装、Reader Canary、Retro、Learnings 回写。

两条用户路径

探索型路径：从模糊种子开始

/story-office-hours → /story-autoplan → 作者批准 → Draft。

适用于新故事、类型选择未定、核心冲突和篇幅尚不清晰的情况。

规格型路径：从明确任务开始

/story-spec → 精确范围与验收 → 单个 Skill / Agent 执行。

适用于“重做第二幕危机”“审计第 12 章 POV 漂移”等边界明确的任务。

决策分类

机械决定 创作判断 用户挑战
类别 示例 处理规则
机械决定 补齐缺失字段、更新路径、运行 Bleed Scan、重建章节索引。 静默自动执行，保留日志和证据。
创作判断 两个都成立的危机方案、声音选择、是否保留开放式结局。 给出推荐和代价，在最终批准闸门集中呈现。
用户挑战 系统认为用户指定的主角、类型或结局需要根本改变。 绝不自动决定；陈述用户原意、模型建议、缺失上下文和误判成本。

5. 控制平面能力

控制平面是本次优化的核心交付物。其目标是让现有 Skills 形成一个可预测的系统。

能力 职责 首个实现 成功证据
Router 把用户任务映射到正确的 Skill、范围和执行模式。 story-router.yaml + 路由表。 20 个标准任务路由测试全部通过。
Orchestrator 串联多阶段工作，管理依赖和中断恢复。 story-autoplan、story-run。 从种子到批准计划无需手动复制上下文。
Gate Engine 读取 Artifact 和 Predicate，判断 PASS / CONCERNS / BLOCKED。 模板化 Gate Checklist。 任何推进决定均能指出证据文件。
Readiness Dashboard 统一展示锁定状态、过期文件、开放问题和下一步。 增强 story-status。 用户一次命令可了解项目状态。
Checkpoint / Restore 保存目标、决定、失败尝试、下一步和工作范围。 checkpoints/*.md。 新会话可在两分钟内恢复工作。
Scope Lock 限制修订的文件和故事范围，防止连带改写。 scope-lock.json。 越界编辑被阻止或显式升级。
Invalidation Graph 上游变化后自动标记下游 Artifact 为 stale。 依赖表 + 状态更新器。 修改 Spine 后相关 Scene / Chapter 自动失效。
Learning Store 保存可复用的项目经验、作者偏好和失败模式。 learnings.jsonl。 后续运行能够检索并引用相关经验。

6. 八阶段实施路线图

路线图遵循“先可靠、再编排、后规模化”的顺序。每个阶段均可独立验收； 未通过退出条件不得将下一阶段视为生产可用。

基线冻结与兼容性盘点

P0 预计 3-5 天 无前置依赖

冻结当前 Skill、Agent、模板、教程和项目目录的真实状态，建立唯一的资产清单和缺口基线。

主要任务建立 Skill Inventory；记录触发词、输入、输出、Agent 映射、路径和平台依赖；确认现有教程与真实 Skill 的偏差。
交付物inventory/skills.json、inventory/artifacts.json、兼容性矩阵、基线审计报告。
退出条件所有核心工作流均有 Owner、真实路径、依赖与已知降级模式；没有“未知由谁调用”的 Skill。
失败回退若资产无法统一命名，先建立 Alias Registry，不在此阶段强制批量重命名。
1

Codex 原生化与基础可靠性修复

P0 预计 1-2 周 依赖阶段 0

解决现有审计已确认的 Agent 路由、Wiki 缺失、路径分裂、Blindness 降级和隐私告知问题。

主要任务建立旧 Agent 名称到 mck-agent-* 的映射；Wiki Optional Fallback；统一 drafts/{slug}/characters/；修复 author: claude；增加 Persona 隐私前言；标记隔离能力。

失败回退保留兼容读取，采用“双读单写”：旧路径可读，新产物只写标准路径。
2

Artifact 契约、状态模型与 Readiness Dashboard

P0 预计 2 周 依赖阶段 1

统一 lifecycle.json、state.json 和各类 Markdown Artifact 的职责，建立可机器检查的交接协议。

主要任务定义 Artifact Manifest；为核心 Skill 增加输入/输出/Predicate/Invalidation 契约；实现 stale 检测；升级 story-status。
交付物story-manifest.json、Schema、Gate Registry、Readiness Dashboard、状态迁移脚本。
退出条件任何项目都能回答：当前状态、缺失证据、过期 Artifact、开放决定、阻塞项和下一步。
失败回退Schema 校验先以 warning 模式运行；完成两个真实项目迁移后再设为 blocking。
3

发现、规格与自动计划编排

P1 预计 2-3 周 依赖阶段 2

建设三个高层入口，减少用户在几十个 Skills 之间手动选择和复制上下文。

主要任务实现 story-office-hours、story-spec、story-autoplan；建立机械/创作/用户挑战分类；集中最终批准。
交付物Intent Brief、Story Design Doc、Reviewed Plan、Decision Log、Story Readiness 报告。
退出条件从一个模糊种子可以生成经过 Premise、Genre、CI、Structure、Voice 审查的可执行计划；中间机械选择无需逐项询问。
失败回退保留手动命令路径；自动计划任一阶段失败时输出可恢复 Checkpoint，而不是从头重跑。
4

场景、章节与批量起草标准化

P1 预计 2-3 周 依赖阶段 2-3

将现有 Scene → Beat → Prose → Chapter 教程转为强制可执行流程，并为中长篇提供安全批次边界。

主要任务新增 story-chapter；固化 Beat-to-Scene 和 Scene-to-Chapter 契约；建立 Sequence Batch；每批更新 Continuity、Setup-Payoff、Image System 和 Checkpoint。
交付物Chapter Template、Chapter Index、Batch Manifest、Scene/Chapter Gate、Scope Lock。
退出条件至少一个完整 Sequence 可在单次批次中完成场景起草、章节组装、状态回写和局部审计，无元数据泄漏。
失败回退出现 Critical、Canon 冲突或 Backtracking Trigger 时自动停止批次，保留已通过的单场景提交。
5

智能审计路由、独立审查与修订队列

P1 预计 2-3 周 依赖阶段 4

让审计范围与变更范围匹配；把所有发现转成可追踪、可关闭、可止损的 Revision Queue。

主要任务实现 Change-to-Critic Router；隔离 Reader Simulator 和 Surprise Auditor；统一 Finding Schema；关联修订、验证和关闭证据。
交付物audit-router.yaml、revision-queue.jsonl、Blindness Report、Cross-Critic Aggregator。
退出条件局部改句不再触发全稿审计；Spine 变更会触发正确的下游复查；所有 Critical / Major Finding 均有状态和验证证据。
失败回退路由置信度不足时使用保守审计集合，并标记成本；不静默跳过 Critic。
6

检查点、恢复、项目记忆与持续学习

P2 预计 2 周 依赖阶段 2-5

将“上次做到哪里”“什么方法失败过”“作者偏好什么”从会话记忆迁移为可查询的项目资产。

主要任务建立 Checkpoint Protocol、Context Restore、Project Learnings、Author Preferences 和 Operational Learnings；引入 confidence、source、scope、supersedes。
交付物checkpoints/、learnings.jsonl、author-preferences.jsonl、恢复摘要。
退出条件新线程读取最新 Checkpoint 后能准确说明当前目标、已锁定事实、失败尝试、下一步和风险；不会把单项目选择误当成全局偏好。
失败回退学习存储采用 append-only；错误经验通过 supersedes 修正，不原地篡改历史。
7

发布、读者 Canary、Retro 与文档同步

P2 预计 2-3 周 依赖阶段 5-6

将 story-publish 从文件拼装扩展为发布前验证、发布后观察和流程复盘。

主要任务Publish Readiness；Reader Canary；反馈归因；Story Retro；教程/术语/示例与 Skill 变更同步。
交付物Release Manifest、Reader Feedback Schema、Retro Snapshot、Documentation Drift Report。
退出条件一个试点作品完成从种子到 Manuscript、测试读者观察、修订决定和 Retro 的全闭环。
失败回退Reader Canary 只产生证据和建议，不自动重写正文；文档同步中的主观内容必须确认。
8

试点、基准、并行生产与正式推广

P2 预计 4-8 周 依赖阶段 0-7

用短篇、中篇和长篇三个项目验证不同规模，建立基准后再开放并行生产。

主要任务三种篇幅 Pilot；比较基线；压力测试长篇上下文；候选分支并行；Canon Merge Gate；发布迁移指南。
交付物Benchmark Report、Pilot Retros、Production Playbook、Migration Guide、v1.0 Release Checklist。
退出条件连续三个项目无 P0 数据/状态故障；长篇至少完成一个完整 Act；核心 KPI 达标。
失败回退若并行导致 Canon 或 Voice 漂移，退回 Sequence 级串行，仅保留 Critic 和候选方案并行。

现有 Specialist 尽量复用；新增能力集中在高层入口、路由、状态和闭环，不重复创造同类专家。

8. Artifact 与 Skill 契约

每个 Skill 必须像一个可靠的生产节点：知道自己需要什么、能改什么、产出什么、如何证明完成。

统一 Skill Contract

skill_contract:
  name: story-scene
  version: 1.0
  mode: draft
  inputs:
    required:
      - scene_card
      - relevant_characters
      - world_bible
    optional:
      - persona
      - beat_sheet
      - prior_scene
  scope:
    writable:
      - prose/{scene}.md
      - audit/scenes/{scene}-*.md
      - state.json
      - ledgers/*
    upstream_mutation: requires_user_confirmation
  outputs:
    - committed_scene
    - critic_reports
    - state_update
    - checkpoint
  predicates:
    - scene_turns
    - pov_consistent
    - no_annotation_bleed

9. 质量闸门体系

闸门只回答“是否有足够证据进入下一阶段”，不宣称作品已经完美。 每个闸门都必须有 Predicate、证据文件、失败路径和允许的豁免记录。

Gate Required 关键 Predicate 证据 失败回退
Intent Gate 是 Haunt、目标体验、篇幅、类型候选、审美边界明确。 Intent Brief。 继续 Office Hours。
Premise Gate 是 Who / Want / Opposition / Cost 可验证，Premise 不是情节摘要。 Premise Card、Tournament Report。 Premise Slate。
Contract Gate 是 Genre Obligatory Scenes、CI、Counter-Idea、Persona Refusals 无冲突。 Genre、CI、Honesty Report。 CI / Genre / Persona。
Spine Gate 是 II、Progressive Complications、Crisis、Climax、Resolution 因果成立。 Spine Audit。 Spine 或上游 Contract。
Act Gate 是 幕价值旅程、Sequence、预算、幕尾转折和升级成立。 Act Design、Rhythm Table。 Act / Spine。
Scene Gate 是 Objective、Conflict、Gap、Turn、POV、Subtext、Continuity 通过。 Scene Card、Critic Reports。 Beat → Scene Card → Character / Spine。
Chapter Gate 是 Chapter Question、Scene Turn 保留、转场、POV、Hook 成立。 Chapter Audit。 Chapter Assembly。
Draft Gate 是 结构 Predicate、长度密度、Setup-Payoff、Voice、Canon 完整。 Full Audit、Reader Simulation。 Revision Queue。
Publish Gate 是 无 Annotation Bleed、无 stale Chapter、关键线索闭合、Manuscript 可重建。 Release Manifest。 Source Artifact 修复。
Learning Gate 否 Retro、有效经验、失败模式和作者偏好已归档。 Retro Snapshot、Learnings。 完成发布后补写。

闸门状态协议

  • CLEAR：所有 Required Predicate 通过，有证据。
  • CLEAR_WITH_CONCERNS：可推进，但存在明确风险和追踪项。
  • BLOCKED：Required Predicate 失败或输入缺失。
  • STALE：曾经通过，但上游版本变化后证据失效。
  • DEGRADED：可以执行，但隔离、Wiki 或工具能力不足。
  • WAIVED：用户明确豁免；必须记录原因和后果。

10. 状态机与失效传播

状态机用于推进，失效图用于回退。任何上游 Canon 变化都必须自动标记相关下游产物，而不是继续使用过时证据。

失效规则矩阵

变更源 立即 stale 条件性复查 无需复查
Premise Genre、CI、Spine、全部下游。 Persona。 研究资料原文。
Controlling Idea Spine、Crisis/Climax、Act Design、Audit Evidence。 主要人物 Arc、Key Image。 无主题关联的世界事实。
Character Wound / Want 涉及该人物的 Scene Card、Subtext Table。 Spine 和关系网。 未出现该人物的场景。
Spine Event 所属及后续 Sequence、Scene Cards、Chapters、Manuscript。 Setup-Payoff 和 Image System。 此前已闭合且无因果依赖的场景。
Scene Prose 所属 Chapter、Manuscript、该 Scene 的审计证据。 Continuity、Ledger。 其他独立 Scene Card。

11. 审计与修订闭环

审计负责发现和证明问题，修订负责最小化修复，验证负责证明问题已关闭。 三者不能混成一次“整体润色”。

Change Detection读取改动范围、Artifact 类型和上游影响。
Critic Routing选择必要 Critic，确定隔离模式和阅读范围。
Findings证据、严重度、位置、Predicate、建议，不直接重写。
Revision Queue排序、分配修订 Pass、设置 Scope Lock 和止损。
Targeted Patch仅修改被批准的维度和范围。
Re-verification原 Critic 或独立验证器复查。
Close / Backtrack关闭 Finding；重复失败则回溯上游。
State Update更新版本、证据、Ledger、Checkpoint 和学习。

Change-to-Critic 路由

变更类型 Required Critics Optional Critics 不应自动运行
单句或段落改写 Voice、Specificity；若有对话则 Subtext。 Cliché。 全稿 Structure、Cast Balance。
Scene Turning Point 改变 Scene Architect、Continuity、Setup-Payoff。 Subtext、Pacing。 无关幕的全量 Reader Simulation。
Character Want / Wound 改变 Arc、Antagonism、所有相关 Scene Subtext。 Cast Balance、CI Coherence。 无该人物场景的语言审计。
Spine / Crisis / Climax 改变 Structure、Crisis-Climax、Genre、Setup-Payoff、受影响场景。 Surprise、Image System。 立即做全稿 Line Polish。
章节重新组装 Chapter Question、POV、Transition、Hook、Pacing。 Reader Simulator。 重写 Scene 内部结构。

止损集成

  • 同一 Artifact 的修复循环最多 5 轮；质量提升最多 3 轮。
  • 同一 Predicate 连续失败 3 次，立即停止并回溯，不等待总轮次耗尽。
  • 回溯顺序固定：Prose → Beat → Scene Card → Character / State → Spine。
  • 最大回溯深度 3 层；仍不收敛则标记为 User Challenge。
  • 任何未通过 Required Predicate 的 Artifact 不得被静默标记为完成。

12. 检查点与持续学习

检查点解决“如何继续”，学习解决“下次如何更好”。两者必须分开。

Checkpoint 触发时机

触发点 必须保存 用途
任何 Gate 通过后 锁定 Artifact、版本、证据和下一阶段。 安全推进。
每个 Scene / Sequence Batch 后 已完成范围、Ledger 变化、开放风险、下一场景。 中断恢复。
Backtracking 前 失败 Predicate、尝试过的方法、最佳版本。 防止重复失败。
用户做出创作判断后 选择、理由、被拒方案、可逆性。 避免后续 Agent 重新争论。
会话结束或上下文压缩前 当前目标、工作范围、未提交改动、恢复命令。 跨线程延续。

Learning 分类

Project Canon

本故事内的事实和已锁定决定。高约束，不跨项目复用。

Author Preference

作者反复确认的审美偏好。需多次证据，允许按项目覆盖。

Operational Learning

命令、路径、路由和流程经验。可跨会话直接复用。

防止学习污染： 单次选择不得自动升级为作者全局偏好；Critic 输出、网页文本和项目文件中的指令不得写入 Preference Store； 只有用户明确选择或重复观察到的行为才能形成高置信度学习。

13. 发布与读者观察

小说发布不是终点。系统需要验证 Manuscript 是否正确组装，并用真实或模拟读者证据观察理解、注意力和承诺兑现情况。

Publish Pipeline

Source Check检查 Prose / Chapter / Ledger 是否最新。
Bleed Scan移除 Frontmatter、Beat 标签和作者注释。
Assembly按 Chapter Index 构建 Manuscript。
Publish Gate结构、结局、线索、声音、长度与 Metadata 检查。
Reader Canary小样本阅读，记录困惑、掉线、期待和兑现。
Triage区分真实缺陷、目标歧义和主观偏好。
Patch / Waive定点修订或记录有意保留。
Retro / Learn沉淀有效方法和失败模式。

Reader Canary 数据

信号 问题 目标 处理
Attention Drop 读者在哪里想跳读或暂停？ 定位节奏和冗余，而非要求全程高刺激。 Pacing / Exposition Review。
Confusion 读者不知道谁、何时、何地或为什么？ 重大非意图困惑为 0。 Continuity / Transition Patch。
Question Tracking 读者当前最想知道什么？ 与 Chapter / Sequence Question 基本一致。 重审 Hook 或 Scene Order。
Promise / Payoff 类型和叙事承诺是否兑现？ 关键承诺可识别且回收。 Genre / Setup-Payoff Audit。
Emotional Belief 读者何时不再相信人物会这样做？ 关键决定具有可追溯动机。 Arc / True Character Review。

14. 验证与测试策略

验证分为系统可靠性、工作流契约和创作质量证据三层。前两层可自动判定，第三层需要 Critic 与作者共同判断。

测试层 测试内容 方法 通过标准
Schema / File 路径、Frontmatter、必填字段、引用和 JSON 有效性。 静态校验器、Fixture。 核心模板 100% 结构有效。
Routing 任务是否选择正确 Skill、Critic 和范围。 标准任务集与期望路由。 核心 20 场景无 P0 路由错误。
Gate 缺失、失败、stale、waived 是否正确判定。 正反 Fixture。 无假 CLEAR。
Invalidation 上游变更是否标记正确下游。 依赖图测试。 无漏标 Required 下游。
Recovery 中断后是否只重跑缺失步骤。 故障注入、Checkpoint 恢复。 已完成 Artifact 不被覆盖。
Privacy Persona 私密内容是否进入发布产物。 发布扫描。 私密文件和字段零泄漏。
Creative Predicate Scene Turn、Crisis、POV、Subtext 等。 专家 Critic + 反例 Fixture。 高置信度结构缺陷可检出。
End-to-End 从 Seed 到 Publish 的完整生命周期。 短篇、中篇、长篇 Pilot。 状态、产物、闸门和恢复全链路闭合。

最低 Fixture 集

  • 缺失 Premise 的非法项目。
  • Spine 已修改但 Scene 未标 stale 的项目。
  • 同一 Character 分裂到两个目录的迁移项目。
  • 含作者注释、Beat 标签和 Frontmatter 泄漏的 Prose。
  • 无价值转变的 Scene。
  • Hard Choice 伪装为 Crisis Dilemma 的 Spine。
  • Blind Reader 在同上下文执行的降级案例。
  • 发布后修改 Prose 导致 Manuscript 过期的案例。

15. 治理、权限与隐私

创作系统的安全不仅是命令安全，还包括 Canon 权限、私密素材、作者主权和越界修订。

治理领域 规则 执行机制
Canon Mutation Premise、CI、Spine、Character Core 和 World Rule 的修改必须确认。 Upstream Mutation Gate + Decision Log。
Scope Safety 修订不得越过指定 Scene / Chapter / Act 范围。 Scope Lock；越界时停止并申请扩展。
Private Persona 作者只应提交愿意落盘的敏感观察；Persona 默认不发布。 隐私提示、private 标记、Publish Exclusion。
Provenance 不再硬编码 author: claude；记录工作流来源和执行模式。 generated_by、workflow_source。
Blindness Honesty 不能隔离时不得声称“盲读”或“全新视角”。 blindness: degraded。
Waiver 用户可跳过非安全 Gate，但必须知道风险。 Waiver Log：原因、范围、后果、日期。
Documentation Drift Skill 行为改变后，教程、术语表和实例必须同步。 Docs Drift Check。

16. 指标与看板

指标用于发现流程弱点，不用于把文学价值压缩成单一分数。

维度 指标 目标 警戒线 行动
可靠性 Required Gate 假通过数。 0。 任何 1 次。 停止推广，修 Gate Engine。
恢复 新会话恢复到有效工作的时间。 < 2 分钟。 > 10 分钟。 改进 Checkpoint 完整性。
路由 不必要 Critic 调用率。 < 15%。 > 35%。 调整 Change-to-Critic Router。
结构 Scene Gate 首轮或小修通过率。 > 70%。 < 50%。 检查 Scene Card / Act Design。
修订 Same Predicate Repeat。 ≤ 2。 3。 触发 Backtracking。
连续性 每 10 Scene 的 Major Continuity Findings。 随项目推进下降。 连续两批上升。 审计 State / Ledger 更新。
声音 Voice Drift Finding 密度。 稳定或下降。 跨批次明显上升。 重载 Persona / Voice Anchors。
读者 非意图重大困惑点。 0。 核心欲望或因果不清。 优先修结构和转场。
流程 发布后因文档或 Artifact 过期导致返工。 0。 任何 P0 返工。 加强 Publish Gate。

17. 风险矩阵

风险按发生概率与影响评估。P0 风险必须在 Pilot 前关闭；P1 风险必须有缓解措施和 Owner。

风险 概率 影响 等级 缓解措施 触发回退
旧 Agent 路由在 Codex 中失效 高 高 P0 Alias Registry、Capability Ladder、路由测试。 改为明确 in-context 执行并标记降级。
上游变更未传播，继续使用旧 Scene 高 高 P0 Versioned Dependency、stale 标记、Publish Gate。 停止 Draft，重建最小受影响范围。
自动修订损坏作者声音 中 高 P1 Diagnosis-first、Scope Lock、Voice Recheck。 恢复前一版本，转人工批准。
并行 Draft 导致 Canon 分裂 中 高 P1 分支隔离、Canon Snapshot、Merge Gate。 退回 Sequence 串行。
审计成本随长篇失控 高 中 P1 变更感知路由、局部默认、增量报告。 仅 Gate 时运行全稿审计。
Persona 私密内容进入版本库或 Manuscript 中 高 P1 隐私告知、private 标记、Publish Exclusion。 阻止发布并清理泄漏。
指标驱动造成文学趋同 中 中 P2 指标只评流程风险；保留 Waiver 和作者主权。 移除误导性评分。

19. 30/60/90/180 天计划

时间线按能力成熟度推进。每一阶段都要求真实项目验证，而不是只完成文档。

周期 必须完成 真实项目验证 Go / No-Go
0-30 天 阶段 0-1；修复 P0 路由、路径和隐私问题。 一个现有项目完成迁移和核心命令回归。 核心生命周期在 Codex 无死路。
31-60 天 阶段 2-3；契约、Dashboard、Office Hours、Autoplan。 从新种子生成可批准 Story Plan。 状态和 Gate 可解释，无假 CLEAR。

21. 最终验收标准

以下条件全部满足，项目才可宣布完成 v1.0 控制平面改造。

  • 核心生命周期在 Codex 中没有不可执行的 Agent 跳转。
  • 新项目由统一模板初始化，旧项目有明确迁移路径。
  • 所有核心 Skill 声明输入、输出、Scope、Predicate 和失效范围。
  • Story Readiness Dashboard 可正确识别 CLEAR、BLOCKED、STALE 和 DEGRADED。
  • 修改上游 Canon 后，下游 Artifact 自动标记 stale。
  • 从模糊种子可通过 Office Hours 和 Autoplan 形成批准计划。
  • Scene → Chapter 流程以正式 Skill 执行，并通过 Chapter Gate。
  • 审计发现进入 Revision Queue，修订后有独立验证和关闭证据。
  • Blind Reader 无隔离时明确标记降级，不产生虚假独立性声明。
  • Checkpoint 可让新会话在两分钟内恢复准确上下文。
  • Persona 私密内容不会进入 Manuscript 或公共发布产物。
  • Publish 可检测 stale Manuscript、Annotation Bleed 和未闭合关键 Ledger。
  • 完成短篇、中篇和长篇一幕三类 Pilot，并形成 Retro。
  • 连续三个 Pilot 无 P0 状态、路由、隐私或数据丢失故障。
  • 教程、术语表、操作实例和 Skill 行为保持同步。

Definition of Done

v1.0 完成： 用户能够从种子开始，使用少量高层命令完成计划、起草、章节组装、审计、修订、发布和复盘； 系统能够解释当前状态、证明为什么可以继续、在失败时定位回溯层级，并在跨会话和长篇项目中保留 Canon、声音与决策历史。

第一批实施范围：阶段 0-1。
